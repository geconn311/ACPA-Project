🔬 Section B: Flush+Reload Hardware Implementation

In our kitchen analogy, "clearing the counter" represents evicting cached lines so that subsequent accesses are forced to fetch from DRAM.

1. The x86 clflush Instruction

On modern processors, an unprivileged user process can execute clflush [address]. This instruction flushes the 64-byte cache line containing that address from all cache levels (L1, L2, and shared L3/LLC) back to DRAM, invalidating the tag.

2. What if clflush is blocked? Evict+Reload

On architectures without an unprivileged flush (such as older ARM or locked hypervisors), attackers perform Evict+Reload. The attacker allocates an Eviction Set (a collection of addresses that map to the exact same cache set) and reads them in a loop. The hardware LRU (Least Recently Used) replacement policy automatically evicts the victim line to DRAM!

🔬 Section B: The Von Neumann Memory Wall & Pipeline Bottlenecks

1. The Classical 5-Stage RISC Pipeline

Without pipelining, an instruction takes 5 clock cycles before the next instruction can start (CPI = 5). Pipelining overlaps the execution stages so that 1 instruction finishes every single clock cycle (ideal CPI = 1):

  • IF (Instruction Fetch): Retrieves 32-bit instruction word from I-Cache at Program Counter (PC).
  • DE (Decode / Register Fetch): Decodes opcode and reads operands from register file.
  • EX (Execute / ALU): Evaluates arithmetic (+, -, OR) or calculates branch targets.
  • ME (Memory Access): Reads/writes D-Cache or off-chip DRAM for load/store operations.
  • WB (Writeback): Commits ALU or loaded values into destination registers.

2. Why Memory Access (ME) is the Primary Bottleneck (The Memory Wall)

While on-chip ALU execution runs at 3–5 GHz (sub-nanosecond timing), off-chip physical DRAM capacitors take 50–100ns (hundreds of clock cycles) to activate wordlines and charge bitlines. This staggering gap is known as the Memory Wall. Multi-level caches (L1, L2, L3) are specifically engineered to prevent the CPU pipeline from continually stalling!

🔬 Section B: DRAM Physics & The Page Table Entry (PTE) Rowhammer Exploit

1. Physical DRAM Capacitor Physics: Where Do Bits Flip?

Critical Concept: The attacker rapidly activates the Aggressor Rows (wordlines), but the bit-flips occur in the adjacent unaccessed VICTIM ROW!

Each DRAM bit consists of 1 transistor and 1 tiny capacitor. Because memory cells are packed nanometers apart, toggling the voltage on an aggressor wordline hundreds of thousands of times per refresh window induces parasitic capacitive cross-talk. The charge in the neighboring victim capacitors leaks away before the scheduled memory refresh, flipping 1 → 0 or 0 → 1!

2. How an Attacker Turns a Bit-Flip into Root / Kernel Takeover

Random data corruption isn't useful by itself. In Google Project Zero's landmark exploit, attackers turn bit-flips into full kernel control via Page Table Entry (PTE) Overwriting:

  1. The attacker allocates thousands of Page Tables across memory (memory spraying).
  2. Double-sided rowhammering is executed until a single bit flips inside the Physical Page Number (PPN) field of a PTE.
  3. The flipped bit points the user process's virtual memory mapping to another Page Table page instead of normal user data!
  4. The attacker now has direct write access to page table mappings, granting arbitrary Read/Write access to all physical RAM, bypassing all OS permission rings (Ring 0 / Root execution)!
